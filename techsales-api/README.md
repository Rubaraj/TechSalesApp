# Medicare Hub Server

Node.js + Express + Mongoose backend for the Medicare Hub frontend (`techsales-app/`). Implements Phase 1 of [`MONGODB_BACKEND_PLAN.md`](../MONGODB_BACKEND_PLAN.md).

## Quickstart

```powershell
# 1. Install
cd techsales-api
npm install

# 2. Configure
copy .env.example .env
# Edit .env if your Pi is reachable at a different host.

# 3. Run
npm run dev
# -> http://localhost:4000/api/health
```

## Environment

See `.env.example`. The notable knobs:

| Var | Default | Purpose |
|---|---|---|
| `MONGO_URI` | `mongodb://192.168.0.175:27017/?directConnection=true` | Phase 0 finding: the Pi's `rs.conf()` advertises an unresolvable hostname; `directConnection=true` is required to bypass topology discovery. |
| `MONGO_APP_DB` | `medhub_app` | Mutable user-generated data. |
| `MONGO_LOOKUP_DB` | `medhub_lookup` | Read-only reference data. |
| `MONGO_CONNECT_TIMEOUT_MS` | `3000` | One-shot timeout on the startup probe. |
| `FORCE_JSON` | `false` | Skips Mongo entirely; serves from JSON store. |
| `JSON_PERSIST` | `true` | When `false`, JSON writes are in-memory only (CI / "reset on restart" demos). |
| `CORS_ORIGIN` | `http://localhost:5173` | Allowlist for the Vite dev origin. |

## Mode is decided at startup

The backend probes Mongo ONCE at boot. The result locks the data layer for the lifetime of the process — no heartbeat, no per-request fallback. See plan §4 "Mode decided once at startup".

- Mongo reachable + `FORCE_JSON=false` → `mode='mongo'`.
- Mongo unreachable, OR `FORCE_JSON=true` → `mode='json'` (reads/writes go to `techsales-api/data/{runtime,lookup}/`).

If Mongo dies AFTER the backend booted in `'mongo'`, requests will 5xx until the process is restarted. This is the deliberate trade-off for a simpler system.

## Endpoints (Phase 1)

| Method | Path | Description |
|---|---|---|
| GET | `/api/health` | `{ mode, mongoUp, dbs: { app, lookup }, uptimeSec }` |

Resource routes (`/api/leads`, `/api/plans`, ...) land in Phase 3+.

## Bootstrap copy

On startup, the server copies any missing files from `data/sample/{runtime,lookup}/` into `data/{runtime,lookup}/`. Existing files are never overwritten — the operator owns the runtime dir. To force a re-seed, delete the file (or run `npm run drop-runtime` once Phase 2b lands) and restart.

In Phase 1 the sample dir may not exist yet (it's generated by Phase 2b's `npm run transform-data`). The bootstrap logs a warning and skips when in mongo mode; in JSON mode with no sample data, it panics with a clear pointer.

## Deployment notes (DEV-ONLY)

- LAN-only; no Mongo auth, no TLS, no application auth.
- Never expose this stack to the public internet without first adding real auth (see plan §13).
- `bindIp` on the Pi should be the LAN subnet only — `0.0.0.0` is unsafe even on a home network.
