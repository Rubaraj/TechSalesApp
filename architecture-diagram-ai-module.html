AI Module — Deep Dive

How /api/ai/* works inside the backend: a single guard chain feeds seven LangGraph agents that share six tools, route every chat call through one provider-switchable LLM chokepoint, and write a full audit trail to MongoDB. Vector retrieval lives in Qdrant; embeddings come from a local Ollama instance.

2. Recommend agent — end-to-end sequence

The most-tools-per-call agent. Walks 4 tools before the LLM call, then logs the full trace. Same shape applies to chatAgent with SSE deltas instead of one JSON response. 
sequenceDiagram
    autonumber
    participant FE as Browser (RecommendedPlansTab)
    participant API as Express controller
(ai.controller.ts)
    participant G as Guards
    participant Ag as recommendAgent (LangGraph ReAct)
    participant Repo as Repository registry
(Mongo / JSON)
    participant Q as Qdrant + Embedder
(Ollama nomic-embed-text)
    participant LLM as LLM provider switch
(getChatModel)
    participant DB as aiInteractions (Mongo)

    FE->>API: POST /api/ai/recommend { leadId }
    API->>G: AI_ENABLED → requireProviderReady → rateLimit → tokenCap
    G-->>API: pass
    API->>Ag: run({ leadId })
    Ag->>Repo: getLeadDetails(leadId)
    Repo-->>Ag: lead profile
    Ag->>Q: searchPlans(query) — embed → ANN top-K
    Q-->>Ag: candidate plans
    Ag->>Q: checkDrugCoverage(planIds, drugIds) — formulary lookup
    Q-->>Ag: tier + PA flags
    Ag->>Ag: calcSavings(plans) (pure JS)
    opt when LLM decides a side-by-side helps
      Ag->>Ag: comparePlans(planIds)
    end
    Ag->>LLM: rank candidates with rationale
    LLM-->>Ag: ranked JSON
    Ag-->>API: { recommendations, rationale }
    API->>DB: AuditCallbackHandler.flush() (provider, model, tokens, toolCalls, latency)
    API-->>FE: 200 { data: { recommendations, interactionId } }

3. Provider comparison matrix

DimensionOllama (default)Anthropic
Model qwen2.5:7b (premium slot identical until GPU box) claude-sonnet-4-6 default · claude-opus-4-7 premium
Cost Free Pay-per-token (Anthropic Console; Max plan does not include API credits)
API key needed No Yes — ANTHROPIC_API_KEY
Where it runs Docker on laptop, port :11434 api.anthropic.com over HTTPS
Tool-call reliability (multi-step) ~75–90% first-pass on a 5-tool chain ~95–98%
Recommend latency (laptop CPU) 15–40 s 3–8 s
Streaming chat Supported, ~3–8 tok/s Supported, much faster TTFB
Best for Free-tier POC, offline demos, no-budget development Production-quality output, low latency, high tool-call accuracy
Both providers go through the same getChatModel() chokepoint. No agent code changes when you flip — just one env var. Embeddings (Ollama nomic-embed-text) and vector storage (Qdrant) are provider-independent.

5. How to switch providers

One-line env change, no code modification:

GoalSet in techsales-api/.env
Free local POC AI_LLM_PROVIDER=ollama · OLLAMA_LLM_MODEL=qwen2.5:7b
Production (Claude Sonnet) AI_LLM_PROVIDER=anthropic · ANTHROPIC_API_KEY=sk-ant-…
Restart the API after the change. Verify via GET /api/health — it returns aiProvider: "ollama" or "anthropic", and the frontend header pill ("AI: Ollama" / "AI: Claude") updates after the next login.
