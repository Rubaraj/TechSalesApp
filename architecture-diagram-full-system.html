Medicare Hub — System Architecture

A dual-mode Medicare sales + member portal: React frontend talks to a Node/Express API that reads from MongoDB on a Raspberry Pi (with a JSON-file fallback for offline demos). An optional AI module — built on LangGraph + Qdrant + a switchable LLM provider — augments six user-facing features without altering the core CRUD path.

Theme

Solution stack by layer

A four-layer architecture. Every layer is built on production-grade, industry-standard tooling. The AI layer is provider-switchable: the same agent code runs against either a local open-source model or Anthropic's Claude — only an API key is needed to enable production-grade reasoning.

Why this stack

LayerHighlights for management
Frontend Modern, mainstream React stack. Same toolchain used by enterprise teams across the industry; easy to staff and maintain.
Backend Stateless Node.js API with strong input validation (zod), structured logging (pino), per-user rate limiting, and clean separation of concerns — production-ready foundations.
AI orchestration LangChain + LangGraph is the de-facto open standard for agentic AI applications. Tool calling, streaming, retrieval-augmented generation, and full observability are built in. Provider-switchable: swap from local open-source LLM to Anthropic Claude with a single environment variable — no code change.
Data MongoDB for transactional data, Qdrant for semantic search, full audit trail of every AI call (cost, latency, tool invocations) for governance and reporting.
Decision needed from leadership: approve an Anthropic API key so the AI layer can run on Claude (Sonnet 4.6 / Opus 4.7) in production. The platform is already built and tested end-to-end against the open-source fallback model; flipping to Claude is a one-line config change and unlocks materially higher response quality, faster end-to-end response time on our deployment, and better tool-call reliability on multi-step agent flows.

Key flows

  1. Login — FE posts to /api/auth/login. On 5xx or network error the FE locks the session into local mode and serves bundled JSON; on 4xx the credentials are authoritatively rejected (no silent fallback).
  2. Lead create + AI recommend — Sales agent submits the lead form (POST /api/leads). After save, the FE fires an asynchronous POST /api/ai/recommend { leadId }. The agent walks getLeadDetails → searchPlans (Qdrant ANN) → checkDrugCoverage → calcSavings and asks the active LLM to rank the candidates. The full trace plus token counts and tool latency lands in aiInteractions.
  3. Member chat — Member opens portal, the floating chat widget posts to POST /api/ai/chat with Accept: text/event-stream. Tool-call events and token deltas stream back over SSE so the user sees "Searching plans… Checking drug coverage… Composing answer" in real time.
